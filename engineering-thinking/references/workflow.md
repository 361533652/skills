# 标准工作流

每个代码改动都必须经过的强制 10 阶段流程。跳过阶段是导致修复糟糕的最常见原因。

## 完整流水线

```
观察 → 理解 → 定位 → 建立上下文 → 假设 → 取证 → 计划 → 修改 → 验证 → 审查
```

### 阶段 1：观察

把现象作为原始事实捕获。不要臆测。

- 逐字读取错误信息 / 堆栈跟踪 / 报告。
- 记录确切环境：操作系统、运行时版本、分支、提交。
- 尽可能复现问题。能复现的 bug 等于解决了 80%。
- 记录：发生了什么、何时、在什么输入下、频率、从何时开始。

**本阶段禁止：** 形成假设、指责某个具体文件。

### 阶段 2：理解

在看代码前，围绕现象在脑中建立系统模型。

- 这个子系统应该做什么？（读文档 / README / 注释。）
- 边界在哪里？（输入、输出、副作用。）
- 正常的快乐路径是什么？
- 这个现象在架构中处于什么位置？

如果系统不清晰，先加载 `architecture.md` 把它梳理清楚。

### 阶段 3：定位

找到行为起源的确切文件 / 函数 / 行。

- 搜索错误字符串、日志关键字或异常类。
- 沿堆栈跟踪追溯到最深处应用帧（跳过框架帧）。
- 用 grep / 符号搜索找到入口点。
- 收窄到尽可能小的代码区域。

**本阶段产出：** 一个具体的文件路径和行范围，而不是猜测。

### 阶段 4：建立上下文

阅读定位到的代码周围，直到周边行为清晰。

- 读取包含可疑行的函数。
- 读取它的直接调用方——如何被调用？
- 读取它的直接被调用方——依赖什么？
- 检查影响该路径的配置文件、环境变量、特性开关。
- 检查这些文件的近期 git 历史（`git log -p -- <file>`）。

**规则：** 如果你无法用一句话解释这段代码为何存在、如何被触发，说明上下文还不够。继续读。

### 阶段 5：假设

形成候选根因。先不改。

- 列出 2–5 个合理的根因。
- 按基础概率为每个打分（见 SKILL.md 根因概率评分表）。
- 按概率从高到低排序。
- 把每个假设写成可被证伪的陈述："如果 X 为真，那么做 Y 应当使现象消失。"

加载 `investigation.md` 获取详细假设技巧。

### 阶段 6：取证

在修改前证明或证伪每个假设。

- 添加临时日志 / 打印语句确认可疑路径。
- 在失败点检查运行时值（变量、配置、数据库状态）。
- 检查该假设是否能解释所有观察到的现象，而不只是一个。
- 若某个假设通过了所有取证检查，置信度上升。
- 若证据与假设矛盾，丢弃它——不要"反正改了再说"。

**置信度门槛：** 仅当置信度 > 40% 时才进入计划阶段。见 SKILL.md 的基于置信度的修改决策表。

### 阶段 7：计划

在动手前写出修改计划。这是强制的。

计划必须包含（完整模板见 `planning.md`）：

- 对问题的当前理解
- 可能的根因
- 仍待排除的替代解释
- 置信度水平
- 要改动的文件
- 预期影响（什么会坏、什么被修）
- 回滚策略

**没有书面计划，不得修改代码。**

### 阶段 8：修改

做针对根因的最小改动。

- 遵循 `code-modification.md` 中的原则。
- 最小改动：只动根因需要动的地方。
- 一个问题 → 一个提交 → 一个逻辑改动。
- 不要在同一改动里重构、重命名或"顺手清理"无关代码。

### 阶段 9：验证

证明修复有效且没破坏其他东西。见 `verification.md`。

- 编译 / 类型检查 / lint。
- 运行相关测试。
- 检查日志有无新警告。
- 测试边界情况。
- 在认为任务完成前，审查完整 diff。

### 阶段 10：审查

对照原始计划和系统自检改动。

- diff 是否与计划一致？有无计划外改动？说明或回退。
- 修复的是根因，还是只是症状？
- 这次改动会不会在其他地方回归？怎么发现？
- 是否应补充一个防止回归的测试？

## 禁止的流转

| 从 | 到 | 状态 | 原因 |
|---|---|---|---|
| 观察 | 修改 | 禁止 | 没有理解、没有计划。 |
| 观察 | 计划 | 禁止 | 没有定位根因。 |
| 假设 | 修改 | 禁止 | 没有收集证据。 |
| 修改 | （完成） | 禁止 | 验证和审查是强制的。 |

## 何时回退

| 触发条件 | 回退到 |
|---|---|
| 证据与假设矛盾 | 假设 |
| 计划暴露上下文缺失 | 建立上下文 |
| 验证失败 | 计划（重新计划） |
| 同一区域编辑 ≥ 2 次仍坏 | 恢复模式 |

恢复模式定义见 `anti-loop.md`。
