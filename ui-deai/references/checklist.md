# AI 味检查清单（9 大类）

## 1. 布局套路化

**典型症状：**
- "Hero + 三列 Feature 卡片 + FAQ + CTA" 是几乎所有 AI 生成落地页的默认模板，页面结构高度雷同
- 什么内容都做成卡片：功能、统计、团队成员、价格方案、用户评价全部卡片化，页面变成"卡片展板"，缺少真正的版式变化
- 千篇一律的 Hero Section：大标题 + 副标题 + 两个按钮 + 背景渐变
- 左图右文、右图左文机械交替
- 大量左右对称、居中排版，看起来"端正"但没个性；所有 section 之间间距完全一致，没有节奏变化
- 固定挂一条"统计数字条"：大字号数字 + 短标签横排（如"10,000+ 用户""99.9% 可用性""500+ 企业信赖"，英文项目常见"10K+ Users · 99% Uptime"这种用 `·` 分隔的紧凑格式），且数字往往是编造的、无来源
- Navbar 永远是"Logo + 居中导航 + 右侧按钮（+ 深色模式切换）"，Footer 永远是"4 列链接 + social icon 排 + copyright"，一看就是模板拼出来的
- 移动端适配机械：桌面 `grid-cols-3` 直接切成 `grid-cols-1`，没有针对手机重新组织信息优先级，只是简单地一列堆叠
- 整个页面正中间放一个居中的悬浮细长卡片，像"弹窗式全页布局"，缺少真实产品该有的信息密度和结构

**修复方向：**
- 打破均匀网格，用不对称布局、错落排版
- 卡片不是唯一的内容容器：统计数据可以用大数字+短句代替卡片，评价可以用引用式排版，价格方案可以用对比表而不是三张卡片
- 不同 section 用不同的布局结构，制造视觉节奏；间距有大有小，重要内容给更多留白
- 减少无意义的装饰性 section；统计数字条没有真实数据支撑就直接不放
- 移动端不是简单堆叠：按内容优先级重新编排/合并，而不是原样堆一列
- 不要把整页做成"正中间一个悬浮卡片"，按真实产品该有的信息密度铺开内容
- **⚠️ 结构级修复优先于样式级修复**：只换配色、调圆角、去 emoji，但 section 结构、数量、顺序原封不动，页面骨架没变，依然"一眼假"。判断页面整体是否是"Hero + 三栏Feature + 统计条 + CTA + Footer"标准 AI 模板，是的话必须先重新设计信息架构（合并/拆分 section、换成时间线/对比表/引用式排版等），再谈局部样式

## 2. 排版机械化

**典型症状：**
- 字号严格按 14/16/18/24/32 这类标准步进走，标题、副标题、正文、按钮层级"教科书感"很重
- Section 标题写法套路化："Simple pricing""Powerful features""Built for teams""Why choose us" 这类通用营销标题到处照搬
- 文案长度和卡片高度被刻意拉齐（每条 feature 描述都凑成差不多字数，只为视觉整齐），显得机械
- 只用系统默认字体堆叠（`-apple-system, BlinkMacSystemFont, "Segoe UI", ...` 或干脆不设置 `font-family`），全站没有一个有个性的字体，字体选择跟产品调性没有任何关系

**修复方向：**
- 字号按内容重要性走，不套公式，允许打破标准步进制造对比和层级张力；字号层级最多 3 级，不要每个元素都不同字号
- Section 标题写具体的、跟产品实际相关的内容，不用通用营销标题模板
- 文案长度服务内容本身，长短不齐没关系，不必刻意凑字数对齐卡片高度
- 至少引入一个跟产品气质匹配的字体（标题字体可以和正文不同），不要只依赖系统默认字体堆叠

## 3. 配色 AI 感

**典型症状：**
- 紫蓝渐变（`linear-gradient(135deg, #667eea, #764ba2)` 及其变体）、青蓝科技风渐变特别多
- 高饱和度撞色，多种鲜艳色混用；深色背景 + 霓虹色文字/边框
- 几种"默认审美"组合反复出现：黑底+紫色高亮、深色背景+青蓝发光、白底+默认蓝主按钮+紫粉辅助光
- 所有按钮/卡片都带彩色渐变
- **标题文字用渐变色**（`background: linear-gradient(...); -webkit-background-clip: text; color: transparent;` 或 Tailwind 的 `bg-gradient-to-r ... bg-clip-text text-transparent`）—— 这是最容易被漏检的一条，很多人只查渐变背景，不查渐变文字
- 配色方案对比关系保守，安全但没记忆点，像是从 "AI website color palette" 搜出来的，缺少品牌感

**修复方向：**
- 主色不超过 2 个，大面积用中性色（灰、白、米）
- 用同一色相的不同明度，而不是多色相拼接
- 渐变如果要用，控制色差范围，别跨色相；强调色只用在关键交互元素上，不要到处都是
- 标题一律用实色，渐变文字直接删除，不做"温和版渐变"这种妥协
- 建立有记忆点的品牌色，而不是"安全但无个性"的默认搭配

## 4. 视觉效果堆砌

**典型症状：**
- 所有元素都是 `border-radius: 12px~24px` 大圆角，`rounded-xl`/`rounded-2xl` 到处都是
- 卡片、按钮、输入框风格完全一致，像同一套组件硬铺全站，"统一"但显得没认真设计过
- 阴影很轻、描边很淡、毛玻璃（`backdrop-blur`/glassmorphism）很多，典型"现代 SaaS 默认风"
- 大量渐变背景、发光效果（glow）、径向发光背景、彩色模糊光斑（blurred gradient blob）、赛博感氛围光之类的纯装饰效果，背景只负责"营造高级感"却不服务内容，甚至抢走信息层级

**修复方向：**
- 圆角分层次：按钮 4-6px，卡片 8px，不要所有元素一个值
- 组件应该有"性格"分工，不要用同一套按钮/卡片/输入框样式覆盖所有场景——主按钮和次按钮、核心区块和状态区块的视觉处理应该不同，不是所有东西都温和柔软圆润
- 少用毛玻璃/发光/径向光/模糊光斑这类"现代 SaaS"标配效果，没有实际功能作用就直接删；背景优先用实色或低装饰处理，让内容而不是背景成为视觉主角
- 不是每个容器都需要阴影，用边框线或背景色区分层级也行；阴影和描边按层级择一使用，不要都加

## 5. 装饰元素通用化

**典型症状：**
- 每个标题/列表项前都挂 emoji（🚀 快速部署 / ✅ 安全可靠 / 💡 智能分析），页面里超过 3 个不同 emoji
- 清一色 Lucide/Heroicons 风格的线性图标，毫无业务特征，用 icon 组件本身没问题，但选择完全通用
- 配图是抽象几何图形、聊天气泡、假的数据面板截图，一看就是"demo 素材"而不是真实产品截图，导致"像 demo，不像产品"
- 到处挂 Badge/Tag 装饰（"New""Popular""Hot""推荐"之类的小标签贴满卡片和列表项），没有实际筛选/分类作用，纯粹为了"看起来丰富"

**修复方向：**
- 删除所有装饰性 emoji，正式业务界面不用 emoji；仅在非正式场景（空状态提示、轻量引导）保留极少量
- 图标要用就选跟产品调性匹配的，而不是随手从通用图标库塞一个
- 插画/配图优先用真实产品截图或具体业务场景图；没有真实素材就别硬配抽象插画凑数
- Badge/Tag 克制使用，只在真的有分类、状态、筛选意义时用，不是装饰品

## 6. 交互动效套路化

**典型症状：**
- 所有按钮 hover 都是放大/变亮/阴影加深，卡片 hover 统一 `translateY(-2px) + shadow`，套路一致到闭眼都能猜到效果
- 弹窗、tab 切换、skeleton loading "该有的都加了"，但只是为了"看起来完整"，不是因为信息层级真的需要
- 动效存在感很强，喧宾夺主，不服务任何实际交互反馈需求
- 用组件库默认的 spinner 图标当 loading 态，跟产品视觉毫无关系；页面里塞了没有实际分组作用的分割线，纯粹为了"看起来有结构"

**修复方向：**
- hover 效果按元素重要性区分，不是每个可点击元素都要位移+阴影套餐；有的用颜色变化，有的用下划线
- 只在真正需要反馈的地方加动效（比如提交后的 loading），不要为了"显得精致"批量加
- skeleton/modal 等交互模式先看业务是否真的需要，不需要就不加
- loading 态设计得贴合产品调性，不是随手套一个默认 spinner；分割线只在真的需要分组时用，没有作用就删

## 7. 内部内容泄露（严重）

**典型症状：**
- HTML 注释 `<!-- TODO: ... -->` 被渲染可见
- 设计稿的标注文字（"间距 16px""字号 14"）出现在页面上
- 组件的 `title`/`alt`/`aria-label` 里写着内部说明而非用户文案
- 开发调试信息（组件名、状态值、日志）显示在界面上
- placeholder 文字是 "请输入内容" "在此输入" 等 AI 默认文案没替换
- 代码注释内容通过某种方式渲染到了页面上

**修复方向：**
- 删除所有面向开发者的可见内容
- 检查所有 `title`/`alt`/`placeholder` 属性，确保是面向用户的文案
- 条件渲染的调试信息确保生产环境不展示
- 把内部注释从 HTML 注释改为框架注释（如 `{/* */}`、`<%# %>`），避免输出到 DOM

## 8. 文案 AI 腔

**典型症状：**
- "为您提供""助力您的""一站式解决方案""赋能""沉浸式体验""高效协作""智能驱动""流畅体验""全新升级""极致体验""实时互动平台""强大功能"
- 英文项目里 "Seamless""Powerful""Effortless""Unlock""Next-generation""Streamlined""Intelligent""Boost productivity""Modern solution""Real-time collaboration" 这类营销词堆砌
- 每个功能描述都是"通过 X 技术，实现 Y 能力，提升 Z 效率"的三段式；标题写得像广告文案，不像真实产品页面
- 描述"正确但空泛"，没有具体场景和约束限定
- 按钮文字过于正式："立即开始体验" → 应该是"开始"或"试试"；英文项目里 "Get Started""Learn More""Try for Free" 这类模板化按钮文字到处照搬
- 空状态提示："暂无相关数据，请稍后再试" → 应该像人说话

**修复方向：**
- 用口语化的短句，像产品经理写的而不是 AI 写的
- 按钮文字 2-4 个字就够；描述说人话，别堆术语，写具体场景而不是形容词堆砌

## 9. 缺乏真实产品感

**典型症状：**
- 假数据太"标准"：John Doe、12,345 users、99.9% uptime、$29/mo 这类一眼假的占位数据
- 表格/图表/列表数据过于整齐，不像真实业务会出现的脏乱数据和例外情况
- 缺少边界状态、异常状态、长文本溢出、空状态的真实处理——只做了"理想路径"的一份数据填满所有卡片
- 信息密度不自然：要么大片留白但没内容支撑（太空），要么每块都塞满标题+描述+标签+按钮（太满），像是把需求点全部摆上去，没有基于业务做优先级取舍

**修复方向：**
- 假数据换成看起来合理、有细节的数字（不是圆整的 10,000/99.9% 这种"演示级"数字），或明确标注是示例数据
- 主动设计至少一种边界/异常/空状态，不要只覆盖理想路径
- 信息密度按实际内容量决定：内容少就精简 section 不硬撑，内容多就克制不塞满
